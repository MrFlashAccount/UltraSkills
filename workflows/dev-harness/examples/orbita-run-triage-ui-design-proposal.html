Solution-independent contract

Make stuck work obvious and actionable.

An operator should understand what needs attention, why, and which safe action resumes the run within ten seconds.

Functional + interaction
  • Must: order runs by operator attention, not recency alone.
  • Must: expose the active step, stop reason, and one safe next action without opening raw state.
  • Must: preserve selection and focus when live events reorder the queue.
  • Should: allow keyboard-only triage of consecutive runs.
Information + quality
  • Must: distinguish user decision, worker failure, approval wait, and environment stop without relying on color alone.
  • Must: contain long run IDs, branch names, and stop summaries without horizontal page overflow.
  • Must: keep destructive actions out of the first-read path.
  • Should: show freshness without noisy continuous animation.
Scope + basis

Extends the current Orbita dashboard vocabulary: lane, run, step, artifact, and attention signal. It does not redesign workflow authoring, logs, or the approval protocol.

Domain map

Run owns progress; attention signal owns urgency.

The queue is a projection. It presents state but does not invent workflow status.

Relationship map

Operator → Attention queue → Workflow run

Workflow run owns ordered steps and current cursor. A stop or approval produces an attention signal. Artifacts and results remain evidence attached to the producing step.

  • One run has zero or one current attention signal.
  • One selected run exposes one bounded next action.
  • Queue order may change; selected run identity must not.

N-01

N-02

Emphasis

N-03

Containment

Long identifiers truncate in queue and wrap only inside detail.

N-04

Focus

Opening detail focuses its heading; closing returns to the selected run.

N-05

Motion

Reorder uses position transition only when selection is unaffected; reduced motion updates instantly.

Primary action describes the next surface, not the underlying runner command.

# Input contract

Start from a task and repository context. The architect normalizes the desired
outcome, boundaries, known constraints and acceptance signals while inspecting
only the relevant code/docs. An issue URL is optional.

Prior research, approved architecture, UI references and existing verification
requirements may be supplied. They remain evidence/constraints; neither an
approved research Canvas nor an execution plan is required to enter Build It.
No separate intake, research report, analogue survey or planning artifact.

A missing user-owned direction, API/compatibility choice or implementation-critical
fact uses a focused non-blocking stop. Unknowns are not fabricated. The architect
produces the executable design and the user approves it before code changes.

Implementation consumes that approved Canvas, actual gate decision, disjoint
backend/frontend/architect owner zones, and exact selected review branches. The
parent orchestrates delegated workers rather than implementing their zones.
Missing delegation or required role material uses the runner's non-blocking-stop
channel; it does not authorize fallback.

Independent post-implementation review is part of Build It. Publication stays outside.

R · Solution-independent contract

What must the interface make true?

Write short, prioritized requirements before showing a composition. This section defines what every later approach must satisfy, not how the selected design works.

Functional requirements

F · CAPABILITIES
  • MUST<User capability or task the interface must enable.>
  • MUST<State, action, or recovery path the user must reach.>
  • SHOULD<Valuable capability that may yield to a documented constraint.>

Interaction requirements

I · BEHAVIOR
  • MUST<Trigger, selection, focus, or return behavior.>
  • MUST<Mouse, keyboard, and touch behavior where applicable.>
  • SHOULD<Effort, continuity, or reversibility expectation.>

Information requirements

C · CONTENT
  • MUST<Facts, hierarchy, or state the first read must communicate.>
  • MUST<Explanation or next action required for failure/empty/waiting states.>
  • SHOULD<Detail to defer, truncate, or reveal progressively.>

Quality / non-functional

Q · CONSTRAINTS
  • MUST<Responsive, accessibility, containment, or compatibility constraint.>
  • MUST<Required behavior under dense, delayed, or degraded conditions.>
  • SHOULD<Perceived performance or progressive-loading expectation.>
